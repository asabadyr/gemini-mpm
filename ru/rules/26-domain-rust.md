# Предметный пакет: Rust (`26`)

## 1. Память, типы и безопасность (`🔴`)
| Область | Ловушка / Запах кода | Обязательная практика |
|---|---|---|
| **Заимствование против клонирования** | Бездумное использование `.clone()` или `Arc` на каждый чих для подавления ошибок borrow checker'а, что приводит к деградации производительности и фрагментации кучи | Грамотно проектировать жизненные циклы (lifetimes) и использовать заимствование (`&str`, `&[T]`) везде, где возможно. Клонирование оправдано только для разделения владения или после профилирования узких мест |
| **Алгебраические типы данных и типажи** | Эмуляция классического ООП-наследования через сложные иерархии `trait` с множественным включением состояния, что противоречит семантике Rust | Использовать мощь алгебраических `enum`, паттерн `newtype` для строгой типизации доменных значений и композицию типажей (traits) для определения общего поведения без связывания состояния |
| **Дисциплина ошибок и запрет паник** | Злоупотребление `.unwrap()` или `.expect()` на внешних данных или при разборе структур; смешивание библиотечного и бинарного подходов к ошибкам | Использовать тип `Result<T, E>` и оператор `?` для проброса ошибок. В библиотеках (crates) применять крейт `thiserror` для типизированных ошибок, а на границах бинарных приложений — `anyhow::Context`. **Строгий запрет на панику** (вызов `unwrap`/`expect`) при обработке внешних или рантайм-входов |
| **Изоляция и доказательство `unsafe`** | Размазывание `unsafe` блоков по всему коду без явной необходимости, игнорирование контрактов безопасности, нарушение алиасинга указателей | Инкапсулировать любой `unsafe` код в безопасные обёртки. Обязательно снабжать каждый блок `unsafe` комментарием `// SAFETY:`, где математически или логически доказывается, почему инварианты компилятора не нарушены |

## 2. Асинхронность и архитектура крейтов (`🟡`)
| Область | Ловушка / Запах кода | Обязательная практика |
|---|---|---|
| **Неблокирующий async и потокобезопасность** | Использование блокирующих I/O операций внутри `async` функций (замораживание потоков-воркеров `tokio`) или удержание стандартного `std::sync::Mutex` через точку `.await` (ведет к дедлокам) | Выносить всю тяжелую синхронную работу в `tokio::task::spawn_blocking`. Использовать каналы `tokio::sync::mpsc::channel` с ограниченным размером буфера. Для синхронизации асинхронного состояния применять `tokio::sync::Mutex` (если удержание блокировки пересекает `.await`) |
| **Модульность и инкапсуляция** | Создание монолитных крейтов с десятками тысяч строк кода или раскрытие внутренних структур данных через глобальный `pub` | Поддерживать гранулярность модулей: размер не более `<=` 400-600 LOC. Ограничивать видимость с помощью `pub(crate)` и `pub(super)`, чтобы предотвратить утечку деталей реализации за пределы приватных подсистем |
| **Производительность итераторов и коллекций** | Ручные циклы с мутацией состояния там, где применимы итераторы, или динамическое расширение векторов по одному элементу | Максимально использовать функциональный стиль с итераторами, так как они компилируются в оптимизированный машинный код без оверхеда. Обязательно инициализировать коллекции известных размеров через `Vec::with_capacity(n)` для избежания реалокаций |
| **Каноническая проверка и CI/CD** | Коммит непроверенного кода, игнорирование предупреждений компилятора, пулл-реквесты без прогона тестов | Каноническая проверка перед каждым пулл-реквестом обязательна: `cargo clippy --all-targets --all-features -- -D warnings && cargo test`. Код с предупреждениями линтера не должен допускаться к слиянию |
