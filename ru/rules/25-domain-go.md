# Предметный пакет: Go (`25`)

## 1. Архитектура пакетов и интерфейсы (`🟡`)
| Область | Ловушка / Запах кода | Обязательная практика |
|---|---|---|
| **Узкие потребительские интерфейсы** | Преждевременное создание громоздких интерфейсов на стороне поставщика (producer), имитирующих ООП-классы, или возврат интерфейса вместо конкретной структуры (`struct`). Это ломает композицию и усложняет тестирование зависимостей в других пакетах | Неукоснительно следовать правилу *accept interfaces, return structs*. Интерфейсы должны определяться там, где они используются (на стороне потребителя), и быть максимально узкими (1-3 метода, как `io.Reader` или `io.Writer`), что позволяет легко подменять зависимости (duck typing) |
| **Запрет помоек `util` и `common`** | Создание универсальных пакетов `utils`, `common`, `helpers` или `types`, куда сваливается разнородный код. Это приводит к размытию ответственности, циклическим импортам и невозможности понять, за какую предметную область отвечает пакет | Группировать файлы по доменам и функциональным границам (например, `http/server`, `domain/auth`, `storage/postgres`). Имена пакетов должны быть короткими, выразительными и говорить о содержимом. Никогда не использовать пакетные имена, не несущие смысловой нагрузки |
| **Глобальное состояние и побочные эффекты `init()`** | Открытие сетевых соединений, подключение к базам данных или чтение переменных окружения внутри функции `init()`, а также использование глобальных мутабельных переменных на уровне пакета | Строгий запрет на побочные эффекты в `init()`. Любая инициализация должна быть явной, возвращать ошибки и вызываться из `main()`. Все зависимости должны передаваться через внедрение (Dependency Injection), а состояние должно инкапсулироваться внутри конкретных структур |

## 2. Параллелизм, память и сеть (`🔴`)
| Область | Ловушка / Запах кода | Обязательная практика |
|---|---|---|
| **Жизненный цикл горутин и `context.Context`** | Запуск «висячих» горутин (fire-and-forget) через `go func()` без передачи контекста и явного механизма остановки, что гарантированно приводит к утечкам памяти (goroutine leaks) при ошибках или закрытии соединений | Передавать `context.Context` первым аргументом (`ctx`) во все функции, работающие с сетью или I/O. Контролировать жизненный цикл горутин: прослушивать `ctx.Done()` для раннего возврата, использовать `errgroup.WithContext` для синхронизации и `SetLimit` для ограничения параллелизма |
| **Потокобезопасность и копирование мьютексов** | Конкурентная запись в `map` из разных горутин без синхронизации (panic: concurrent map writes) или случайное копирование структур, содержащих `sync.Mutex` по значению | Защищать `map` через `sync.RWMutex` или использовать `sync.Map` для специфичных паттернов. Структуры с мьютексами и сами мьютексы всегда передавать только по указателю. Запрет на неявное копирование состояния блокировок |
| **Дисциплина ошибок и оборачивание** | Использование голого `if err != nil { return err }` с потерей стек-трейса и контекста вызова, либо форматирование ошибок через простой `fmt.Sprintf` | Использовать оборачивание ошибок через `fmt.Errorf("action failed: %w", err)` для сохранения оригинальной ошибки. Для проверки типов и значений ошибок использовать исключительно канонические функции `errors.Is` и `errors.As` |
| **Безопасность сетевых клиентов и серверов** | Использование дефолтных `http.Server` или `http.Client` (`http.Get`) без заданных таймаутов подключения и чтения/записи, что делает сервис уязвимым к атакам Slowloris и бесконечным зависаниям | Всегда явно настраивать `ReadTimeout`, `WriteTimeout` и `IdleTimeout` для серверов. Для клиентов использовать таймауты или `context.WithTimeout`. При успешном HTTP-вызове обязательно вызывать `defer resp.Body.Close()` |
| **Каноническая проверка и гонки данных** | Отправка кода в репозиторий без проверки на наличие состояний гонки или статических ошибок, игнорирование предупреждений линтера | Использовать каноническую команду проверки в CI и локально: `go vet ./... && go test -race ./...`. Любое предупреждение race detector'а является критическим багом и блокирует слияние (merge) ветки |
