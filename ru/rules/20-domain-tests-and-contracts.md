# Предметный пакет: Качество тестов и пирамида контрактов (`20`)

## 1. Анти-тавтология и мысленная мутационная проверка (`🔴`)
| Ловушка | Запрещённый пример | Обязательный стандарт |
|---|---|---|
| **Проверка только факта существования** | `assert res is not None`, `expect(out).toBeDefined()`, `expect(arr.length).toBeGreaterThan(0)` | Проверять точные значения, переходы состояний, коды/тексты ошибок и реляционные постусловия |
| **Эхо мока (Mock Echoing)** | Замокать хелпер на возврат `X` и проверить, что выход равен `X`, не задействовав бизнес-логику | Проверять трансформацию данных, ветвления, граничные значения и содержимое побочных эффектов |
| **Мысленная мутация (Mental Mutation)** | Зелёный тест без проверки чувствительности к поломке | Перед завершением спроси себя: *«Если инвертировать целевой `if` или заменить `<` на `<=` в прод-коде, упадёт ли хотя бы один тест?»* Если нет — ужесточи ассерты |
| **Дедупликация параметризованных тестов** | Копипаст однотипных тест-функций | Использовать `@pytest.mark.parametrize`, `it.each`/`test.each`, табличные тесты Go вместо копипаста однотипных тест-функций; количество тестов привязано к числу поведений и веток ошибок, а не к ручным комбинациям |

## 2. Детерминизм асинхронности и чистота SUT (`🔴`)
| Правило | Исполнение |
|---|---|
| **Запрет произвольных `sleep()` / `setTimeout()`** | **НИКОГДА** не синхронизировать асинхронные тесты фиксированными паузами (`time.sleep(0.5)`, `await new Promise(r => setTimeout(r, 200))`). Опрашивать наблюдаемое состояние (`waitFor`, промисы событий, детерминированные fake timers) с ограниченным таймаутом |
| **Не мокать сам тестируемый объект (SUT)** | Мокать только внешние границы ввода-вывода (сеть, часы, сторонние API); **НИКОГДА** не стабить внутренние методы самой тестируемой системы (System Under Test) |
| **Запрет тестовых методов в прод-коде** | **НИКОГДА** не добавлять `_for_testing()`, `resetForTest()` или тестовые флаги в продакшен-классы; использовать инъекцию зависимостей через конструктор или тестовые фикстуры |
| **Защита общих фикстур** | Не мутировать на месте модульные/сессионные фикстуры; копировать входные данные на каждый тест и соблюдать существующие `conftest.py` / тестовые хелперы как жёсткие контракты |

## 3. Трёхуровневая пирамида контрактного тестирования (`🟡`)
Для функций с контрактами, финансовых расчётов, парсеров и конечных автоматов выстраивай тесты в 3 уровня:
1. **Уровень 1 — Юнит-тесты постусловий и границ**: Штатные сценарии, пустые/нулевые/максимальные границы, идемпотентность и точные исходы ошибок.
2. **Уровень 2 — Property-Based тесты инвариантов** (`hypothesis` / `fast-check` / `rapid`): Закладывай предусловия прямо в **генераторы** (избегай тяжёлой фильтрации через `assume()`, обедняющей выборку) и проверяй структурные инварианты (round-trip, сохранение сумм, порядок, монотонность).
3. **Уровень 3 — Негативные тесты предусловий**: Подавай невалидные типы, выходы за диапазон, просроченные/битые токены и конкурентные гонки, доказывая явный отказ без частичного повреждения состояния.

## 4. Безопасный многоядерный параллелизм для долгих тестов и расчётных скриптов (`🟡`)
- **Когда применять**: Для CPU-ёмких наборов тестов и локальных батч-скриптов (прогоны сценариев, перебор параметров, симуляции, пакетная обработка `>15–30` сек на независимых кейсах) — не упираться в 1 ядро CPU.
- **Параллелизм тест-раннеров в первую очередь**:
  * Python: `pytest -n auto` (если в venv проекта есть `pytest-xdist`, кроме явно однопроцессных/monkey-patched тестов).
  * JS/TS: пулы воркеров `vitest` / `jest` (`--maxWorkers` / threads).
  * Go / Rust: нативные `cargo test` и `go test -p <cores>` + `t.Parallel()`.
- **Чанкование в локальных скриптах**: Распределять независимые батчи по формуле `workers = min(max(1, (os.cpu_count() or 2) - 1), len(batches), лимит_RAM)` (`ProcessPoolExecutor` в Python; воркер-пулы в Node/Go/Rust).
- **4 инварианта безопасности (`🔴`)**:
  1. **Непересекающееся состояние и детерминированная сборка**: Только read-only входные срезы/пути, запись лишь в раздельные временные пути или возврат значений, детерминированная сортировка результата по порядку входа — **НИКОГДА** не гоняться параллельно в один SQLite/файл.
  2. **Защита `if __name__ == "__main__":` и `spawn`**: Для Python-процессов обязательно использовать `multiprocessing.get_context("spawn")` при наличии потоков, async-циклов, пулов БД или C-расширений/monkey-patching (никогда небезопасный `fork`).
  3. **Без вложенного переподписания CPU**: Выставлять `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `MKL_NUM_THREADS=1` при запуске воркер-процессов.
  4. **Лимит по RAM**: Ограничивать число воркеров по формуле `свободная_RAM / пик_воркера`, передавая пути/индексы вместо копирования огромных датасетов.
