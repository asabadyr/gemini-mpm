# Предметный пакет: Frontend UI (`28`)

## 1. Декомпозиция и управление состоянием (`🟡`)
| Область | Ловушка / Запах кода | Обязательная практика |
|---|---|---|
| **Размер компонентов и логика** | Огромные монолитные компоненты на тысячи строк кода, смешивающие представление, запросы к API и сложную бизнес-логику форм | Строгая декомпозиция UI-компонентов до размеров `<=150-200` LOC. Вся сложная бизнес-логика должна выноситься в чистые функции или кастомные хуки (`use*`, composables, runes), оставляя компонентам только рендеринг и привязку событий |
| **Вычисляемое состояние против синхронизации** | Антипаттерн «копирования пропсов в стейт» и последующая синхронизация через `useEffect`, `watch` или `ngOnChanges`, что вызывает каскадные ререндеры и рассинхрон данных | Использовать производный (вычисляемый) стейт на лету: переменные внутри рендера, `useMemo` (React), `computed` (Vue) или `$derived` (Svelte). Если значение можно вычислить из существующих пропсов и стейта, оно не должно лежать в отдельной переменной состояния |
| **Колокация серверного кеша и UI-стейта** | Размещение ответов API в глобальном Redux/Vuex/Zustand хранилище вместе с UI-стейтом (например, с состоянием открытых модалок) | Строгое разделение: использовать инструменты управления асинхронным серверным кешем (например, `TanStack Query`, SWR или Apollo) отдельно от локального синхронного UI-состояния. Избегать prop-drilling'а через композицию `children` / `slots` |
| **Дизайн-примитивы и вариативность** | Копипаст похожей верстки (JSX/шаблонов) и стилей для кнопок, инпутов и карточек с ручным переопределением CSS-классов в каждом месте использования | Создавать переиспользуемые дизайн-примитивы с задокументированными вариантами (например, через `cva` или `clsx`). Приложение должно собираться из ограниченного набора стандартизированных компонентов-строительных блоков |

## 2. Безопасность, производительность и доступность (`🔴`)
| Область | Ловушка / Запах кода | Обязательная практика |
|---|---|---|
| **Утечки памяти и очистка эффектов** | Подписка на глобальные события (`window.addEventListener`), запуск таймеров (`setInterval`) или сетевых запросов без их корректной очистки при размонтировании компонента | Обязательная очистка подписок, таймеров и инстанцирование `AbortController` для отмены выполняющихся `fetch` запросов в функциях очистки (cleanup functions) внутри `useEffect` / `onUnmounted` / `onDestroy` |
| **Типизация сложных состояний** | Использование множества конфликтующих булевых флагов состояния (например, `isLoading`, `isError`, `isSuccess` одновременно), что порождает невозможные состояния интерфейса | Моделировать сложные состояния через размеченные объединения (Discriminated Unions) или конечные автоматы (State Machines), чтобы тип явно запрещал нахождение в нескольких эксклюзивных состояниях одновременно |
| **Семантика и защита от XSS** | Верстка исключительно через несемантичные `<div>` и `<span>`, а также использование неэкранированных методов вставки сырого HTML из непроверенных источников | Обязательное соблюдение семантической доступности (a11y: атрибуты `aria`, навигация с клавиатуры). Жесткий запрет на использование `dangerouslySetInnerHTML`, `v-html` или `{@html}` без предварительной обработки через строгие HTML-санитайзеры (например, DOMPurify) |
| **Производительность длинных списков** | Рендеринг тысяч DOM-узлов одновременно для больших таблиц или списков, загрузка тяжелых чанков кода для маршрутов, которые пользователь не посещает | Использовать виртуализацию (lazy rendering, `react-window`, `vue-virtual-scroller`) для длинных списков. Применять ленивую загрузку маршрутов и компонентов на уровне роутера для разделения бандла и ускорения TTI (Time to Interactive) |
