# Предметный пакет: SQL, MongoDB и Миграции (`24`)

## Критические правила слоя данных и миграций
| Область | Ловушка | Обязательная практика |
|---|---|---|
| **Формат ID и таймстампов (`🔴`)** | Поиск по полю `ObjectId` строковым hex-значением (или наоборот), а также смешивание секунд Unix (`10` цифр) с миллисекундами (`13` цифр) и объектами `Date` | Сначала проверять реальные документы/строки в БД и схемы моделей; явно нормализовать типы ID и единицы времени на границе репозитория |
| **Формат возврата драйверов и ORM (`🔴`)** | Допущение, что `findOneAndUpdate` / `upsert` возвращает чистый `doc` вместо `{ value: doc }` (или наоборот) при обновлении драйвера (например, MongoDB Node driver v4 → v5/v6) | Сверять точную установленную версию драйвера в lock-файле и покрывать распаковку результата юнит/интеграционными тестами |
| **Фильтры тенанта и активной выборки (`🔴`)** | Пропуск условия `tenantId`/`companyId` или учёт мягко удалённых (`deleted: true`) / отключённых записей в бизнес-логике и аналитике | Обязательно ограничивать все мульти-тенантные чтения/записи ключом тенанта и явно отфильтровывать удалённые/неактивные записи (кроме сырых аудит-логов) |
| **Индексы и безопасность курсоров** | Полные сканы коллекций без индекса, выгрузка `.toArray()` / `SELECT *` без лимита на миллионных таблицах, нарушение порядка составных индексов | Строить составные индексы строго по правилу **Equality → Sort → Range (ESR)**, читать данные курсорами/батчами с пагинацией и запрашивать только нужные поля (projection) |
| **Миграции без простоя (Zero-Downtime)** | Переименование/удаление колонок или навешивание блокирующего `NOT NULL` в одном релизе с обновлением кода приложения | Проводить изменения в 4 шага: **Expand → Backfill → Switch Reads/Writes → Contract**; строить тяжёлые индексы в конкурентном/фоновом режиме (`CONCURRENTLY`) |
| **Неатомарная запись в несколько коллекций** | Обновление зеркалируемого состояния в 2+ таблицах/коллекциях без компенсации и сверки расхождений | Использовать транзакции там, где они поддержаны, либо сочетать идемпотентные upsert / `Promise.allSettled` с явным логированием расхождений и фоновой реконсиляцией |
