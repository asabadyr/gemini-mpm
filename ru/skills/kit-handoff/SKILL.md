# `/kit-handoff` — Пауза сессии, возобновление по живому Git и Postmortem

Обеспечивает непрерывность работы между сессиями и сохранение инженерного опыта без утечки секретов и слепого доверия устаревшим заметкам вместо реального состояния Git.

Определите запрошенную подкоманду из сообщения пользователя (`pause`, `resume` или `postmortem`; по умолчанию используйте `pause` при завершении работы и `resume` в начале новой сессии, если файл `.agents/handoffs/LATEST.md` существует).

---

## Режим 1: `pause` — Запись очищенного 7-секционного слепка (`<=10K` токенов)
1. **Защита через `.gitignore` (`🔴`)**:
   - Проверьте наличие `<workspace>/.git`. Если каталог существует, убедитесь, что `.agents/handoffs/` добавлен в `<workspace>/.gitignore` (добавьте при отсутствии, не индексируя посторонние файлы), чтобы слепки сессий **никогда** не попали в Git.
   - *(Примечание: передача сессии не должна прерывать или убивать работающих фоновых субагентов! Сначала проверьте `manage_subagents(Action="list")` и `manage_task(Action="list")` и зафиксируйте активные ID.)*
2. **Сбор живого состояния репозитория**:
   - Одиночный Git-репозиторий: выполните `git status -s` и `git log --oneline -5`.
   - Зонтичное мультирепо без корневого `.git`: обойдите дочерние `<subrepo>/.git`, собрав непустой `git status -s` и последний коммит по каждому изменённому подпроекту.
3. **Обязательная очистка секретов (`🔴`)**:
   - Просканируйте текст слепка перед записью и замените любые значения секретов (`sk-`, `ghp_`, `AKIA`, `npm_`, `xox`, `AIza`, блоки PEM, `Bearer ...`, строки подключения к БД, пароли) на `<REDACTED:VAR_NAME>`.
4. **Запись `<workspace>/.agents/handoffs/LATEST.md`**:
   - Заполните все 7 секций по шаблону [`resources/LATEST.template.md`](./resources/LATEST.template.md), выдерживая общий объём **`<=10,000` токенов (не более `~40 KB`, оптимально `2–6 KB`)**.
5. **Рекомендация следующего шага**:
   - Подтвердите путь сохранённого файла (`[LATEST.md](file://<workspace>/.agents/handoffs/LATEST.md)`). Если работа продолжается в текущей длинной беседе — порекомендуйте нативную слэш-команду `/compact`; при переходе в новый чат — подскажите запустить `/kit-handoff resume`.

---

## Режим 2: `resume` — Сверка слепка с живым состоянием Git (`🔴`)
1. Прочитайте `<workspace>/.agents/handoffs/LATEST.md` и `<workspace>/.agents/knowledge/memories.md` (если существуют).
2. **Обязательная сверка с живым Git**:
   - Запустите живые команды `git status -s` и `git log --oneline -10` (в корне `<workspace>`, если `.git` есть, или по дочерним подрепозиториям `*/*/.git`).
   - Сравните секции `LATEST.md` §2 (Коммиты) и §6 (Незакоммиченное состояние Git) с фактическим выводом Git:
     - **Живой Git всегда имеет приоритет над текстом слепка.** Явно перечислите любые новые коммиты, переключения веток или изменённые файлы, появившиеся после записи `LATEST.md`.
3. Выведите чёткую 5-строчную **Сводку возобновления** (Цель, Проверенная дельта Git с момента паузы, Нетронутый пользовательский WIP под защитой, Первый следующий шаг) и переходите к работе (либо уточните у пользователя при обнаружении конфликта).

---

## Режим 3: `postmortem` — Выжимка уроков сессии в `memories.md` и `/learn`
1. **Анализ фактов сессии**:
   - Проанализируйте ошибки текущей сессии, вердикты `BLOCK` от Checker, срабатывания правила 3 попыток и корректировки пользователя (при необходимости прочитайте `<appDataDir>/brain/<conversation-id>/.system_generated/logs/transcript.jsonl` через grep и точечное чтение строк).
2. **Обновление базы знаний проекта**:
   - Запишите однострочные датированные выводы (`- [YYYY-MM-DD] <краткий урок>`) в соответствующую секцию `<workspace>/.agents/knowledge/memories.md`, строго соблюдая `FIFO`-квоты из `04-memory-knowledge-adr.md` (`CRITICAL` — 20 без авто-вытеснения; `Environment` — 15, `Decisions` — 20, `Patterns` — 20, `Gotchas` — 15; общий размер `<=4 KB`).
   - Для крупных инцидентов добавьте датированный разбор в `.agents/knowledge/postmortems.md` (или `.agents/knowledge/active-state/engineering-rules-and-postmortems.md`, если используется в проекте) и отразите смену состояния в `00-INDEX.md`.
3. **Мост к `/learn`**:
   - Если исправление пользователя или найденный паттерн применим шире одного репозитория и заслуживает отдельного переиспользуемого скилла или правила, явно порекомендуйте вызвать команду `/learn`.
