# Ручной плейбук: Инициализация и миграция Проектного Адаптера (`90`)

> **Примечание по интерфейсам**: Вызывается в Antigravity IDE / App через `@90-playbook-bootstrap.md`. (В `agy` CLI упоминания правил через `@` не поддерживаются — используйте `/kit-bootstrap`, `/kit-architecture` или `/kit-handoff`, когда подключён плагин `agy-mpm-core-ru` или каталог `skills/`.)

## Режимы работы и авто-переключение
- **`--lite`**: Отдельная библиотека, CLI-утилита или небольшой скрипт (`<5` модулей, без кластерной эксплуатации).
- **`--full`**: Продакшен-сервис, монорепо/мультирепо, деплой в K8s/облако или жёсткие требования конфиденциальности.
- **`--migrate`**: Консолидация и перенос без потерь существующих правил (`GEMINI.md`, `CLAUDE.md`, `.cursorrules` и др.).
- **Авто-переключение**: При обнаружении любых существующих файлов инструкций или правил автоматически включается режим `--migrate`, защищающий от перезаписи и задвоения правил.

## Шаг 1: Read-Only сканирование проекта (`<=60 сек`)
1. **Сканирование топологии и стека**:
   - Определите Git-топологию: корневой `<workspace>/.git` против зонтичного мультирепо без корневого `.git` (`*/*/.git`).
   - Проверьте манифесты стека (`package.json`, `tsconfig.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `Dockerfile`, K8s YAML, Terraform `.tf`, `.mise.toml`, конфиги CI) и `git log --oneline -20` (там, где есть `.git`).
2. **Исчерпывающий поиск существующих правил всех агентов**:
   - Найдите все файлы инструкций для ИИ-ассистентов:
     - `GEMINI.md`, `AGENTS.md` (в корне и подкаталогах), `.agents/rules/*.md`, устаревшие `.agents/workflows/*.md`
     - `CLAUDE.md`, `.claude/**`
     - `.cursorrules`, `.cursor/rules/**`
     - `.windsurfrules`
     - `CODEX.md`, `.remember/**`
     - Разделы для ИИ в `CONTRIBUTING.md`
3. **Шлюз бэкапа без потерь (Lossless Backup Gate)**:
   - Если найден хотя бы один файл правил или инструкций, скопируйте их все без изменений в:
     `<appDataDir>/brain/<conversation-id>/scratch/rule-migration-backup/`
     с сохранением относительных путей до любых правок в проекте.
4. **Определение режима**:
   - Если найдены файлы инструкций или пользователь запросил миграцию — переходите в **`--migrate`**.
   - Иначе выберите `--lite` или `--full` по сложности стека.

## Шаг 2: Матрица триажа на 4 корзины (для `--migrate`)
Распределите все обнаруженные правила по 4 корзинам:
1. **Корзина 1 (Дубликаты Универсального Ядра)**: Общие запреты, правила clean-code/LOC/DRY/OOP, покрытие item-by-item, шлюзы верификации, защита Git WIP, паттерны секретов, правило 3 попыток, лестница Maker-Checker. -> **Опустить / не переносить** в адаптер (уже предоставляются глобально правилами `00..04`, `20..28`).
2. **Корзина 2 (Поведенческие конфликты)**: Правила, конфликтующие с базовой безопасностью (авто-коммиты без стейджинга, пропуск тестов, изменение чужого WIP). -> **Подсветить и явно согласовать** с пользователем.
3. **Корзина 3 (Постоянная идентичность и Red Lines)**: Назначение репо, карта директорий, канонические команды (`install`, `lint`, `typecheck`, `test`, `build`), топ 3–5 обязательных `🔴` запретов, матрица профилей `Роль -> Точная модель + Effort` (`teamwork` / `swarm` + `Promote-on-Review`). -> Сжать в тонкий `<workspace>/GEMINI.md` (или общий `<workspace>/AGENTS.md`) без фронтматтера (`~1.8–3.8 KB`).
4. **Корзина 4 (Ops, подпроекты, база знаний и воркфлоу)**:
   - CI/CD, K8s, облачный деплой, секреты, ловушки БД -> `.agents/rules/10-project-operations.md` (`trigger: model_decision`).
   - Конфиденциальность и изоляция тенантов -> `.agents/rules/11-project-confidentiality.md` (`trigger: always_on`).
   - Правила подкаталогов -> `.agents/rules/12-<subproject>.md` (`trigger: glob` + `globs: "**/packages/backend/**"` — единая строка в кавычках через запятую, обязательный префикс `**/`, без скобок `{a,b}`; используйте строго ключ `globs:` во множественном числе и никогда не пишите ключ `glob` в единственном числе без `s`!).
   - Архитектурные знания, память, активные задачи -> `.agents/knowledge/{00-INDEX.md, memories.md, active-tasks.md, postmortems.md}`.
   - Устаревшие воркфлоу -> пометить к конвертации в `.agents/skills/<name>/SKILL.md`.

## Шаг 3: Единое подтверждение через `ask_question`
Покажите сводку сканирования, матрицу триажа и задайте вопросы **один раз** через `ask_question`:
1. **Режим и план миграции**: Подтвердите `--lite`, `--full` или `--migrate` и распределение по 4 корзинам.
2. **Режим совместной работы с репозиторием**:
   - `(Recommended) Соло / Antigravity-репозиторий`: Закоммитить тонкий Проектный Адаптер в Git.
   - `Персональный оверлей поверх общего репозитория`: Добавить `GEMINI.md` и `.agents/` в `.git/info/exclude` ТОЛЬКО если `<workspace>/.git` существует как реальная Git-директория (никогда не создавайте фиктивный `.git/info/exclude` в корне зонтичного мультирепо без `.git`, где корневые файлы адаптера и так лежат вне дочерних Git-репозиториев!).
   - `Мульти-инструментальная команда (Claude + Cursor + Antigravity)`: Единый корневой `AGENTS.md` + `.agents/rules/10-*`.
   - `Командный репозиторий с существующими .agents/rules/`: Предупредить о суммировании по `realpath`; рекомендовать отключить `[agy-mpm-core](customization://agy-mpm-core)`, никогда не копируя файлы Универсального Ядра.
3. **Модуль конфиденциальности**: Включать ли `11-project-confidentiality.md`.

## Шаг 4: Генерация Проектного Адаптера (ноль копий Универсального Ядра!)
> **Инвариант анти-дублирования**: Никогда не копируйте (`cp`) правила Универсального Ядра (`00..04`, `20..28`) в `<workspace>/.agents/rules/` при включённом плагине `agy-mpm-core-ru` (дедупликация `realpath` схлопывает только идентичные физические файлы!).

1. **Для `--lite`, `--full` и `--migrate`**:
   - Запишите `<workspace>/GEMINI.md` (**чистый Markdown, БЕЗ YAML-фронтматтера**, `~1.8–3.8 KB`): идентичность проекта, топ 3–5 `🔴` красных линий, карта директорий/подпроектов, канонические команды, блок ссылок `.agents/knowledge/` с подсказкой Knowledge-First Subagent Boot (`knowledge_refs`) и матрица профилей `Роль -> Точная модель + Effort` (для `teamwork` / `swarm` и лестницы `Promote-on-Review` в режимах `--full` и `--migrate`).
   - Создайте `.agents/knowledge/memories.md` со стандартной 5-секционной `FIFO`-шапкой (`CRITICAL` — 20 без авто-вытеснения, `Environment` — 15, `Decisions` — 20, `Patterns` — 20, `Gotchas` — 15, общий размер `<=4 KB`).
   - Интеграция с Git: для персонального оверлея обновите `.git/info/exclude` ТОЛЬКО при наличии реальной Git-директории `<workspace>/.git` (никогда не создавайте фиктивный `.git/info/exclude` в корне зонтичного мультирепо без `.git`!); для соло/команды при наличии `<workspace>/.git` добавьте `.agents/handoffs/` и `.agents/teamwork/` в `.gitignore` (идемпотентно, сохранив существующие строки).
2. **Дополнительно для `--full` и `--migrate`**:
   - `.agents/rules/10-project-operations.md` (`trigger: model_decision`): CI/CD, безопасные команды деплоя в K8s/облако, маппинги namespace, скрипты секретов и аналитические ловушки.
   - `.agents/rules/11-project-confidentiality.md` (`trigger: always_on`, опционально): неразглашение тенантов/клиентов, облачных проектов, ПДн и внутреннего стека.
   - `.agents/rules/12-*.md` (`trigger: glob` + `globs: "**/<subdir>/**"`, опционально): правила подкаталогов (обязательный префикс `**/`, без `{a,b}`, строго множественное число ключа `globs:` — без единственного числа!).
   - `.agents/knowledge/{00-INDEX.md, active-tasks.md, postmortems.md}` (с аккуратным слиянием, если файлы уже есть).

## Шаг 5: Обязательный шлюз проверки без потерь
При миграции существующих правил или объединении адаптера:
- Выполните антагонистическую сверку (или вызовите `code-critic`, если инструменты субагентов доступны), сопоставив файлы адаптера с бэкапом в `<scratch>/rule-migration-backup/`.
- Подтвердите:
  1. 0 потерянных проектных инвариантов, команд, регулярных выражений или ссылок.
  2. 0 скопированных дубликатов Универсального Ядра в рабочем пространстве.
  3. Каждый файл в `.agents/rules/` весит строго `<24,000` байт и имеет валидный фронтматтер.
  4. Файл `GEMINI.md` не содержит фронтматтера.
